# Background jobs

Everything Aggregor runs that no command started: timers, polls, watchers, the processes it leaves running, and every
call that leaves the machine. Each window runs its own copy of the extension's jobs. Keep this table to what runs now:
add, change or delete a row in the same commit as the code.

Only `gh` and git's fetch from origin reach the network; every other job stays on the machine.

The `make` of `BackgroundJobs` (`infrastructure/di/backgroundJobs.layer.ts`) starts every job an application service
runs for the window's life: `SessionService.syncSessionTabsWithTmux` first, then the rest together. A watcher an
implementation or a view runs starts in its own `make`, and a job a webview or command asks for starts with it.
